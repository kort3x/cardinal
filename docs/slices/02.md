# Outcome

Populate multiple zones and transfer cards while page layout, depth, and card populations change.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Add one authoritative membership/order model, atomic multi-card scene updates, and grid layout. All zones accept zero/one/many cards and carry arbitrary names.
- Support CSS page anchors and explicit spatial geometry under one stage/camera. Project owns zone placement; engine owns card arrangement. Resolve coordinate systems before layout.
- Project spatial zones consistently; preserve CSS anchors' screen footprints when depth changes. Track resize/scroll, temporarily hidden zones, and reappearance without measuring zero-sized anchors as destinations.
- Commit membership once, solve all affected card targets, and animate displaced neighbors together. Reconcile snapshots by ID and reject invalid membership/capacity changes atomically.

## Acceptance criteria

- [x] Repeated transfers always land at the requested grid slot without home rectangles, DOM reparenting, or post-landing reassignment.
- [x] Mixed positioning, depth changes, page scroll and window resize produce no endpoint jump or stale geometry.
- [x] Hidden zones preserve membership and stop accepting input; deletion of an occupied zone requires explicit reassignment/removal.
- [x] Batch updates and reduced motion reach the same final state; no card belongs to two zones.

## Runnable lab scenario

Transfer six cards among three zones, resize and scroll mid-flight, and hide/restore one anchored zone.

## Implementation progress

Working implementation added on 2026-09-15; issue #2 is closed and this slice is
in Review pending sign-off.

- Public atomic transfers and `zone` updates validate membership, finite geometry
  and final batch capacity before mutation.
- Grid tracks account for mixed dimensions; transfers and resizing move displaced
  neighbors together. Geometry reconciliation preserves unrelated motion channels.
- CSS-selector anchors resolve through the WebGL camera and track page placement,
  resize, scroll, hiding and reappearance. Hidden cards lose rendering/focus/hit input.
- The primary card lab now includes three responsive CSS-anchored zones arranged as
  tall Archive and Workbench columns with a shorter centered Reserve zone, plus
  selected-card transfers, slot selection, and membership/count status. The
  standalone `examples/card-engine-lab/zones.html` remains the focused regression
  fixture for mixed CSS-anchor and spatial-zone behavior.
- Deterministic zone tests, `npm run test:chrome:zones`, and
  `npm run test:chrome:main-zones` cover the engine and integrated lab behavior.
  Current evidence: 81/81 engine tests, 12/12 standalone Chrome zone checks
  (including perspective footprints and ray picking), 5/5 integrated main-lab
  zone checks, 17/17 layout checks, 18/18 element checks, and 18/18 acceptance
  checks in both Firefox 155.0.1 and Safari 26.6.2.
