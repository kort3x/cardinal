# Outcome

Populate multiple zones and transfer cards while page layout, depth, and card populations change.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Add one authoritative membership/order model, atomic multi-card scene updates, and grid layout. All zones accept zero/one/many cards and carry arbitrary names.
- Support CSS page anchors and explicit spatial geometry under one stage/camera. Project owns zone placement; engine owns card arrangement. Resolve coordinate systems before layout.
- Project spatial zones consistently; preserve CSS anchors' screen footprints when depth changes. Track resize/scroll, temporarily hidden zones, and reappearance without measuring zero-sized anchors as destinations.
- Commit membership once, solve all affected card targets, and animate displaced neighbors together. Reconcile snapshots by ID and reject invalid membership/capacity changes atomically.

## Acceptance criteria

- [ ] Repeated transfers always land at the requested grid slot without home rectangles, DOM reparenting, or post-landing reassignment.
- [ ] Mixed positioning, depth changes, page scroll and window resize produce no endpoint jump or stale geometry.
- [ ] Hidden zones preserve membership and stop accepting input; deletion of an occupied zone requires explicit reassignment/removal.
- [ ] Batch updates and reduced motion reach the same final state; no card belongs to two zones.

## Runnable lab scenario

Transfer six cards among three zones, resize and scroll mid-flight, and hide/restore one anchored zone.
