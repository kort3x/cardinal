# Outcome

Change a card's sleeve/frame/art treatment while it remains inspectable and interactive.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Provide theme-driven sleeves, frames and one animated-art or parallax treatment behind optional renderer extensions.
- Preserve canonical scene/card identity, active content face and presentation through treatment changes.
- Pause invisible loops, bound assets/effects and memory, and provide static fallback without delaying card motion.
- Keep localized content and styles isolated from host-page CSS.

## Acceptance criteria

- [ ] Treatment changes during flip/inspection/movement do not replace shells or leak concealed surfaces.
- [ ] Missing/slow media and disabled effects retain readable static cards and responsive input.
- [ ] Measure actual browser performance against slice 01 baselines; no mandatory cosmetic runtime for a basic scene.

## Runnable lab scenario

Switch between a static treatment and animated art, flip to a custom sleeve, inspect it, and disable decoration during travel.
