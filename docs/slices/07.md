# Outcome

Hide title/image/flavour or custom elements and watch the card and its neighbors adapt smoothly, then restore them.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Support identified region addition/removal separately from hide/show with retained content. Explicit zone visibility wins over card preferences; leaving restores the card baseline.
- Add preserve-space and reflow behaviors; fixed-size and content-driven shell dimensions with constraints, no leftover collapsed gaps, and explicit anchor/pivot handling.
- Resolve region geometry before zone placement. Animate shell dimensions and affected neighbors together; default destination presentation changes during travel.
- Handle delayed fonts/images and interrupted region transitions without stale cleanup. Avoid discrete rewrap jumps using stable wrapping/coordinated reveal.

## Acceptance criteria

- [ ] Each of title/image/flavour/custom regions may disappear and return alone or in combinations, including an empty card.
- [ ] Hiding flavour shortens an auto-height card without scaling its other content; a fixed-size card retains dimensions.
- [ ] Changes during move/rotate/scale/flip preserve anchors, shell identity, and unrelated animation progress.
- [ ] Hide/show/remove/re-add races, asset loading and zone changes cannot remove newer elements or create landing jumps.

## Runnable lab scenario

Shorten a moving card by hiding flavour, remove its image, add a custom field, then restore content while its neighbors rearrange.
