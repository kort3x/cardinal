# Outcome

Add, update and remove multiple independently identified elements while a card is moving or changing shape.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text German; repository docs/comments/tests English. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Add registered attachment types and per-card instance IDs; stamps, counters, stickers and custom content share lifecycle/presentation rules.
- Support flow placement that can resize the shell and overlay placement anchored to card/region with local offsets, clipping and layer order.
- Implement content-face/back affinity, missing-anchor hide/fallback policy, project-localized labels and optional controls.
- Keep updates incremental and cleanup generation-safe; effects on focused/hidden elements must not leave active invisible controls.

## Acceptance criteria

- [ ] Multiple same-type attachments coexist; counter changes preserve instance/card identity and other elements.
- [ ] Add/remove/re-add during movement or a flip cannot resurrect old instances or delete replacements.
- [ ] Overlay anchors follow changing geometry; flow attachments participate in the card's resize animation.
- [ ] Hidden surfaces and removed focused attachments have correct input/accessibility behavior.

## Runnable lab scenario

Stamp a travelling card, increment a counter, add two stickers, hide their image anchor, and remove one sticker mid-flip.
