# Outcome

A second standalone consumer uses the public package without Picko assumptions and passes a reproducible interaction gallery.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text German; repository docs/comments/tests English. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Build examples/card-engine-use/ with unrelated content, arbitrary zone names, distinct project rules and different surrounding CSS.
- Consume only the public package entry point; verify no imports of Picko/legacy state, markup, CSS or poll server.
- Run the lab journey across arrangements, transactions, faces, multi-selection, card/element attachments, inspection, targeting and pacing.
- Document runnable examples, interface contracts and measured supported device/card-count envelope.

## Acceptance criteria

- [ ] Browser matrix includes Chromium/Firefox/WebKit, touch layouts, keyboard and reduced motion.
- [ ] Benchmark 6/50/200 cards with varying moving cohorts/templates; record missed frames and input latency against reference thresholds.
- [ ] One scene shell per card survives journeys; previews are separately identified; stable-viewport landing delta stays within one CSS pixel.
- [ ] Dependencies on legacy modules or undeclared host CSS are absent; all optional effects can be disabled.

## Runnable lab scenario

Run the same move/rotate/scale/flip, group-drag and dynamic-content journey in the lab and second consumer.
