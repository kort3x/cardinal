# Outcome

Drag a card to a permitted destination, preview its placement, and accept or reject the action through project rules.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

Implementation sequence and proposed interaction interface:
[`docs/plans/drag-interactions.md`](../plans/drag-interactions.md).

Implementation is in progress. Extended automated acceptance passes: 121 engine
tests, 17 Chrome drag checks, 10 Chrome geometry/lifecycle checks, and 25 checks
each in Firefox and Safari. The drag-preview path was optimized to avoid repeated
deep snapshot cloning and normalization; the 50-card first-update spike improved
from 96.2 ms to 31.9 ms in the rerun. Physical-touch/Surface checks remain
separate. The lab's Performance diagnostics panel now has a **Record next drag**
capture for real mouse, pen, or touch input; the procedure is documented in the
browser-testing runbook. Visual quality checks and the issue closure/project
transition have not been performed.
See [extended verification evidence](../verification/drag-acceptance-2026-09-15.md)
and the retained [initial evidence](../verification/drag-interactions-2026-09-15.md).

- Implement pointer/touch/keyboard move intent with fast rule-provider feedback and rule revision invalidation. Use a batch-shaped request even for one card.
- Use full visible zone surfaces, including empty zones, with arrangement-based insertion. Invalid foreground zones block pass-through; explicitly transparent zones do not. Drag visuals do not block targeting.
- Render insertion previews, pointer capture, auto-scroll, grab offsets, and cancellation. Permit pickup during animation, taking over position while independent rotation/scale/flip continues.
- Emit one drop intent; acceptance commits a transaction, asynchronous acceptance holds a pending preview, and rejection returns to current committed geometry.

## Acceptance criteria

- [ ] Allowed and denied drops behave identically by pointer, touch and keyboard. Denied targets never reserve slots.
- [ ] Rules changing, destination/card removal, pointer cancellation and late asynchronous replies cannot commit a stale move.
- [ ] Dragging remains pointer-attached while zones resize/scroll; released drops use current geometry.
- [ ] Pending/rejected moves leave no ghost gaps, stale focus, or global input lock.

## Runnable lab scenario

Drag to allowed and denied zones, delay acceptance, reject a drop, and pick up a card while it is flipping.
