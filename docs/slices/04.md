# Outcome

Select cards within or across zones and move or act on the entire selection together.

Implementation planning and Luna work assignments:
[selection and batch dragging plan](../plans/multi-card-selection.md).

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Add ordered selection state, primary card, range anchor, project eligibility/count/scope limits, modifier toggle, logical range selection, touch selection mode, and keyboard controls. Optional rectangle selection must not hijack card dragging.
- Dragging a selected card preserves the set. Freeze cohort/order at pickup and preserve relative poses by default; support an explicit compact bundle for widely separated selections.
- Evaluate permissions/capacity for the full batch, preview all target positions, and emit one intent. Default to atomic acceptance/rejection, never silently drop denied members.
- Support batch rotate/scale/flip and attachment/presentation commands through the same transaction model; per-card pivots remain independent. Keep selection separate from persistent groups.

## Acceptance criteria

- [x] Same-zone reordering resolves indices after removing selected members; cross-zone selections have deterministic project-visible order.
- [x] One denied card or insufficient batch capacity rejects the whole move. Cancellation returns each survivor to its current source arrangement.
- [x] Member removal, external membership changes and late approval cannot partially commit a stale batch.
- [ ] Selected shells retain identity and individual face/transforms. Successful moves preserve valid selection; pointer/touch/keyboard workflows are covered.

Implemented locally with automated desktop coverage. The final acceptance gate
retains fresh physical touch/pen evidence and the desktop Safari touch-driver
limitation; see [implementation evidence](../verification/batch-acceptance-2026-09-16.md).

## Runnable lab scenario

Select cards across two zones, drag them together into a third, reject then accept the batch, and flip the selection without moving it.

In the main lab, open **Drag → Set up batch**. It selects one card from Lake and
one from River; drag to Ocean and use **Reject**, then repeat with **Accept**.
**Flip selection once** acts in place. Choose **Compact bundle** or **Touch
selection** before setting up the fixture, since changing these input options
recreates the lab scene.
