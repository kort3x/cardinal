# Outcome

A stamp or card arrival produces a coordinated pulse/trail/impact and optional sound that cancels cleanly.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Connect presentation milestones to optional anchored effect/audio consumers. Support pulse, trail or impact examples without affecting layout or hit testing.
- Use the scene clock and generation lifetime for once-only cues, pause/cancel/destroy, mute and reduced-motion settings.
- Provide bounded asset readiness/fallback, effect budgets and disposal; decoration degrades before interaction or text quality.

## Acceptance criteria

- [ ] Skipped/superseded operations never emit late audio or effects; actual milestones fire once.
- [ ] Effects follow moving/resizing card or region anchors and cannot block drop targeting.
- [ ] Stress bursts, missing audio/art, mute, reduced motion and destroy; verify resource cleanup and baseline latency/frame budget.

## Runnable lab scenario

Stamp and deal cards with synchronized feedback, interrupt the sequence, mute it, and run a high-volume burst.
