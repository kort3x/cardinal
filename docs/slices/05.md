# Outcome

Change a populated zone's arrangement and see the same cards move coherently into the new layout.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text English; localization may be added later. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Implement aligned rows/columns, fans, deterministic scattered piles, and explicitly ordered stacks alongside grid.
- Specify gaps, alignment, spread, overlap, card ordering and overflow per zone. Respect actual card dimensions; uniform sizing is optional.
- Support explicit scrolling, intentional overlap, bounded fit, or rejection; no silent unlimited shrinking or cross-zone spill.
- Use one solver for rest poses and interaction previews; reordering and population changes animate all affected cards.

## Acceptance criteria

- [ ] Layout changes preserve IDs, faces, data and stack order; pile scatter is stable across solves.
- [ ] Empty/single/many cards and mixed-size fixtures produce deterministic targets without unintended overlap.
- [ ] Minimum-size/overflow settings hold across responsive bounds and depth; reduced motion reaches identical layout.

## Runnable lab scenario

Cycle a populated zone through every arrangement, reorder the stack, and stress the configured overflow policy.
