# Outcome

Choose valid targets across input methods and see their relationships follow moving cards; move a declared group atomically.

## Design and constraints

Build fresh code in `packages/card-engine/` and new examples, not incremental changes to legacy engine files. Backward compatibility is out of scope. Read the full accepted requirements in parent specification #1; this slice adds only the behavior listed below. Keep app/lab labels and accessibility text German; repository docs/comments/tests English. Use the same public interface in consumers and tests. Do not publish/deploy as part of implementation.

## Scope

- Add target sessions with eligible IDs, min/max counts, source, localized instructions, confirm/cancel and revalidation on project updates.
- Render anchored links/arrows following current transformed card/region geometry, with explicit endpoint-removal behavior.
- Implement persistent groups separately from transient selection, including collapsed/expanded views, inspection access, and atomic group move intent.
- Project rules define meanings and eligibility; no combat or business logic is implemented in the engine.

## Acceptance criteria

- [ ] Moving/resizing endpoints keep links attached; removing a target mid-session safely invalidates it.
- [ ] Pointer/touch/keyboard choose the same permitted targets and respect selection counts.
- [ ] Grouped moves preserve member IDs/order and reject atomically; collapsed cards remain inspectable without hidden input leaks.

## Runnable lab scenario

Choose two eligible cards as targets while they move, remove one before confirmation, then expand and move a persistent group.
